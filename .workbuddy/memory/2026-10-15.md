# 2026-10-15 工作日志

## blade-tool 代码安全 & 性能审查（静态审查，未改代码）

针对 blade-tool 全部 422 个 Java 文件（~4.6万行）做了安全+性能专项审查，关键发现：

### 高危（已逐一验证）
1. **DataScope SQL 拼接注入**：`blade-starter-datascope/.../BladeDataScopeHandler.java:65,69,82` 用 `StringUtil.format` 把 `scopeColumn`/`scopeField`/`whereSql`(CUSTOM 模式 scopeValue) 原样拼入 SQL，未参数化。CUSTOM 模式 sql 模板值来自 bladeUser(JWT)。
2. **租户头绕过 / 空租户忽略**：`blade-core-secure/.../SecureUtil.java:288-297,306-314` 直接信任 `Tenant-Id` 请求头优先于 token 租户；`blade-starter-tenant/.../BladeTenantHandler.java:84-88` 租户为空时 `ignoreTable()` 返回 true → 整条查询不做租户过滤。
3. **@Async 无线程池**：`blade-core-boot/.../BladeBootAutoConfiguration.java:39 @EnableAsync` 未定义 `taskExecutor`/`applicationTaskExecutor` Bean，回退 `SimpleAsyncTaskExecutor`（每任务新建线程，日志监听高频触发 → 线程爆炸/OOM）。

### 中危
- 权限匹配用 `uri.contains` 子串匹配（BladePermissionHandler.java:62）→ 越权面。
- api-crypto AesUtil IV 取密钥前16字节（非随机），仍支持 DES（AesUtil.java:259-265）。
- 报表 UReport 鉴权仅判断 userId>0（UReportAuthFilter.java:143-146），任意登录用户可进设计器；静态资源按扩展名全局放行。
- blade-starter-redis `keys()` O(N) 阻塞命令（BladeRedis.java:288）；`get(key,loader)` 回填无 TTL、空值不缓存、无互斥 → 击穿/穿透/脏数据。

### 性能（中/低）
- SqlLogInterceptor 热路径每次 SQL 执行 `SQLUtils.format` 全量解析。
- DatabaseProvider.getReportFiles() `service.list()` SELECT * 含大 BLOB content。
- BaseServiceImpl.queryOne() 用分页(COUNT+LIMIT)取单行。
- DataScope OWN_DEPT_CHILD 循环逐部门查 DB（冷缓存 N+1）。
- 报表 HttpSessionReportCache/TempObjectCache 用无界非线程安全 HashMap（ConcurrentModificationException/内存泄漏风险）。
- XssHttpServletRequestWrapper 热路径缓存整请求体 + 正则过滤（大文件上传开销）。
- SensitiveUtil.processWithRegex 每次 compile 正则；BladeTenantHandler DCL `scanned` 建议 volatile。

详见会话内审查报告。修复优先级：先 #1 #2（越权/泄露），再 #3（稳定性），然后中危越权面与加密实现。
